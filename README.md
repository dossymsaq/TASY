# Жеткіз 750 — доставка по Астане

Курьерская доставка посылок **до 2 кг** по **Астане** по фиксированной цене:

| Кто платит | Сумма |
|---|---|
| Продавец (наш клиент) — при оформлении заказа | 750 ₸ |
| Покупатель продавца — онлайн по ссылке или наличными курьеру | 750 ₸ |
| **Сервис получает за одну доставку** | **1 500 ₸** |

Цены, лимит веса и районы города задаются в `server/config.js`.

## Состав

```
server/   API + база данных (Node.js 22, Express, SQLite) — отдаёт и сайт
deploy/   установка на сервер: systemd, nginx, HTTPS, бэкапы
web/      сайт: лендинг, кабинеты всех ролей, страница отслеживания /t/КОД (PWA)
mobile/   мобильное приложение iOS/Android (Expo / React Native)
```

## Мягкий старт (`LAUNCH_MODE=soft`)

Чтобы начать работу до договоров с банком и SMS-сервисом:
- **оплата только наличными курьеру**: продавец отдаёт 750 ₸ при передаче посылки, покупатель — при получении;
  обе суммы попадают в кассу курьера, он сдаёт их владельцу (кабинет → «Курьеры» → «Принял»);
- заказ сразу уходит курьерам, без страницы оплаты;
- **вход по паролю**: владелец и курьеры — как обычно; продавец подаёт заявку с паролем, владелец звонит,
  заключает договор и одобряет заявку (или сам создаёт продавца в «Пользователях»);
- **клиентам вход не нужен**: посылку отслеживают по ссылке от продавца или по коду на главной.

Когда будут договоры: уберите `LAUNCH_MODE=soft` (или включайте по отдельности `ONLINE_PAYMENTS=1`, `SMS_LOGIN=1`).

## Роли и входы

Страница входа `/app` предлагает выбрать роль; у каждой есть прямая ссылка — её удобно отправить человеку:
`/app#owner` (владелец), `/app#seller` (продавец), `/app#register-seller` (заявка продавца), `/app#client` (клиент), `/app#courier` (курьер).
**Аккаунты продавцов и курьеров выдаёт владелец**: кабинет → «Пользователи» → «Создать аккаунт» (кнопка «Придумать»
пароль, затем «Скопировать» / «Отправить в WhatsApp» данные для входа); там же «Пароль» — выдать новый пароль.
Магазин, который хочет подключиться, оставляет заявку «Подключить магазин» — она приходит в «Обращения».
(`SELLER_SIGNUP=1` — разрешить продавцам регистрироваться самим, с одобрением владельцем.)
На любой странице есть кнопка «Установить приложение» — сайт ставится на экран «Домой» как приложение (PWA).


- **Продавец** — создаёт заказ, платит 750 ₸, отправляет покупателю ссылку (WhatsApp/Telegram), видит статусы и статистику.
- **Покупатель** — по ссылке (без регистрации) или в приложении: статус и оплата 750 ₸.
- **Курьер** — берёт свободные заказы, «забрал у продавца» → «вручить» (без кода: курьер наш, за доставку отвечает сервис); если покупатель не платил онлайн — принимает 750 ₸ наличными и потом сдаёт их администратору.
- **Администратор** — выручка, заказы, назначение курьеров, отмена с возвратом, сотрудники, блокировка.
- **Техподдержка** — чат-обращения (в том числе от гостей со страницы отслеживания) и поиск заказов.

## Запуск

```bash
cd server && npm install && npm start      # http://localhost:3000
npm test                                    # тесты полного цикла доставки
```

При первом запуске создаются демо-аккаунты (телефон / пароль):
админ `77000000001 / admin123`, поддержка `77000000002 / support123`,
курьер `77000000003 / courier123`, продавец `77000000004 / seller123`,
покупатель `77000000005 / client123`. На рабочем сервере (`NODE_ENV=production`) демо-аккаунтов нет —
первого администратора создаёт команда `npm run create-admin` (см. [deploy/README.md](deploy/README.md)).

Вход для продавцов и покупателей — **по SMS-коду** (регистрация тоже). Сотрудники могут входить по паролю.
В тестовом режиме SMS не отправляются: код показывается прямо на экране, а все сообщения видны в кабинете админа → «Уведомления».

### Настройки сервера (переменные окружения)

| Переменная | Назначение |
|---|---|
| `PORT` | порт (по умолчанию 3000) |
| `PUBLIC_URL` | адрес сайта для ссылок в SMS, например `https://jetkiz750.kz` |
| `SMS_STATUS=1` | включить SMS о статусах заказа (по умолчанию выключены, остаётся только код входа) |
| `SMS_MODE` | `mock` (тест, по умолчанию) или `mobizon` — реальная отправка через Mobizon.kz |
| `MOBIZON_API_KEY`, `MOBIZON_FROM` | ключ API и согласованное имя отправителя Mobizon |
| `OTP_SECRET` | случайная строка для защиты SMS-кодов (обязательно в продакшене) |
| `NODE_ENV=production` | отключает показ тестового кода в ответе API |
| `PUSH_MODE` | `expo` (по умолчанию) или `log` — не отправлять push, только журнал |
| `EXPO_ACCESS_TOKEN` | ключ Expo, если включена защита push |
| `TRUST_PROXY=1` | если сервер стоит за nginx (для правильного учёта IP в лимитах) |
| `PAYMENT_MODE` | `mock` (тестовая страница оплаты, по умолчанию) или `freedompay` |
| `FREEDOMPAY_MERCHANT_ID`, `FREEDOMPAY_SECRET` | данные магазина в Freedom Pay |
| `FREEDOMPAY_TESTING=1` | тестовые платежи на стороне Freedom Pay |
| `DB_FILE` | путь к базе |

### Оплата

Онлайн-оплата идёт через страницу банка: сервер создаёт счёт → продавец или покупатель платит на странице банка →
банк присылает уведомление на `https://<домен>/api/payments/callback/<провайдер>` → заказ становится оплаченным.
При отмене заказа деньги возвращаются через банк автоматически, повторная оплата одного заказа — тоже.
В тестовом режиме вместо банка открывается страница `/pay/mock/…` с кнопками «Оплатить» / «Отказаться».

Подключение Freedom Pay: получить в личном кабинете ID магазина и секретный ключ, задать переменные выше,
указать в кабинете адрес уведомлений `https://<домен>/api/payments/callback/freedompay`, провести тестовый платёж
с `FREEDOMPAY_TESTING=1`. **Адаптер (`server/payments.js`) написан без доступа к документации Freedom Pay —
перед запуском сверьте имена полей и формулу подписи с документацией, которую выдаст банк.**
Kaspi Pay / Halyk ePay подключаются так же — добавлением провайдера в `server/payments.js`.

### Уведомления: push и SMS

Уведомления о заказах приходят push-ом в мобильное приложение. SMS используются только для кода входа;
SMS о статусах заказа выключены (покупателю ссылку отправляет сам продавец, например в WhatsApp).
Включить SMS о статусах для тех, у кого нет приложения, — `SMS_STATUS=1`. Курьеры получают push о каждом
новом оплаченном заказе, поддержка — о новых обращениях, автор обращения — об ответе поддержки.
Журнал всех уведомлений — в кабинете админа → «Уведомления».

Push работают в сборке приложения (EAS Build) на реальном телефоне. Один раз выполните в `mobile/`:
`npx eas-cli@latest init` — команда создаст проект в Expo и запишет его `projectId` в `app.json`.
Для iOS нужен Apple Developer аккаунт (ключ push EAS настроит сам при первой сборке),
для Android — проект Firebase и файл `google-services.json` (см. документацию Expo «Push notifications setup»).

### Уведомления о статусе заказа (push; SMS — при `SMS_STATUS=1`)

| Событие | Кому | Текст |
|---|---|---|
| Продавец оплатил заказ | покупателю | ссылка отслеживания и оплаты 750 ₸ |
| Курьер взял заказ | продавцу | курьер едет за посылкой |
| Курьер забрал посылку | покупателю | курьер в пути |
| Доставлено | продавцу | заказ вручён |
| Отмена | обоим | заказ отменён |

Мобильное приложение:

```bash
cd mobile && npm install
EXPO_PUBLIC_API_URL=http://<IP-компьютера>:3000 npx expo start   # открыть в Expo Go
npx eas-cli@latest build -p android                              # сборка для Google Play / App Store
```

**Демо-версия приложения** (`EXPO_PUBLIC_API_URL=demo`) работает без сервера и интернета: внутри приложения
запускается тот же код из `server/` (SQLite через sql.js, `demo/build-rn.sh` → `mobile/src/demo/backend.generated.js`),
данные хранятся на телефоне, оплата тестовая. Сборка APK:

```bash
bash demo/build-rn.sh                          # после изменений в server/
cd mobile && npx expo prebuild -p android
cd android && EXPO_PUBLIC_API_URL=demo ./gradlew assembleRelease   # → app/build/outputs/apk/release/
# или в облаке Expo: npx eas-cli@latest build -p android --profile demo
```

## Что нужно до запуска в работу

1. **Платежи.** Схема оплаты через банк готова, адаптер Freedom Pay написан. Осталось: договор с банком, ключи, сверка адаптера с документацией и тестовый платёж (см. «Оплата»).
2. **Сервер и домен.** Всё для установки готово — см. [deploy/README.md](deploy/README.md): одна команда ставит
   сервер, nginx, HTTPS, автозапуск и ежедневный бэкап. Осталось: арендовать VPS в Казахстане, купить домен,
   запустить `setup.sh` и настроить копирование бэкапов на второй сервер. (При большом росте — переход на PostgreSQL.)
3. ~~Вход по SMS-коду и SMS-уведомления~~ — готово. Осталось: заключить договор с Mobizon.kz (или другим SMS-шлюзом), согласовать имя отправителя и включить `SMS_MODE=mobizon`.
   Push-уведомления в приложении готовы — осталось выполнить `eas init` и настроить Firebase/Apple (см. «Уведомления»).
4. **Юридическое.** Черновики [публичной оферты](web/offer.html) (`/offer`) и [политики конфиденциальности](web/privacy.html) (`/privacy`) готовы,
   ссылки есть на сайте и в приложении. Осталось: заполнить реквизиты в [квадратных скобках], проверить условия
   (сроки, ответственность, возвраты) и согласовать с юристом. Отдельно — фискальные чеки (ОФД) через кассу
   или платёжного партнёра. Персональные данные по закону РК должны храниться на серверах в Казахстане.
